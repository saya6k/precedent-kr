# precedent-kr 판례 저장소 탐색

대한민국 판례를 Git으로 관리하는 저장소다. **각 판례 = Markdown 파일**, **각 판례의 선고일자 = Git commit date**. 데이터 출처는 [국가법령정보센터 OpenAPI](https://open.law.go.kr).

## 저장소 구조

```
{사건종류}/
  {법원등급}/
    {법원명}_{선고일자}_{사건번호}.md
    {법원명}_{선고일자}_{사건번호}_{판례일련번호}.md   # 합성 키 충돌 시
```

- **사건종류**: `민사` `형사` `일반행정` `세무` `가사` `특허` `선거·특별` `기타`
- **법원등급**: `대법원` `하급심` `미분류`
- **파일명**: 합성 키 `{법원명}_{선고일자}_{사건번호}.md`. 구분자는 `_`. 예: `가사/대법원/대법원_2003-11-14_2000므1257_본소_1264_반소.md`
  - 좌측에서 첫 두 `_`까지가 항상 (법원명, 선고일자) 슬롯. 법원명엔 `_`가 없고 선고일자는 고정 포맷 `YYYY-MM-DD`.
  - 결측 폴백: 선고일자 누락 → `0000-00-00`, 법원명 누락 → `미상법원`(사건번호는 `{판례일련번호}`로 폴백).
  - stem이 UTF-8 180바이트 초과 시 사건번호 슬롯만 자르고 `_{판례일련번호}` 접미사.

## 자주 쓰는 작업

저장소 루트(`precedent-kr/`)에서 실행한다.

```bash
# 특정 판례 보기
cat 가사/대법원/대법원_2003-11-14_2000므1257_본소_1264_반소.md

# 사건번호로 찾기 (파일명 접미사 매칭)
ls 민사/대법원/*_2022다12345.md

# 특정 법원 판례 (파일명 접두사 매칭)
ls 민사/하급심/서울고등법원_*

# 민사 대법원 판례 개수
ls 민사/대법원/ | wc -l

# 전체에서 단어 검색 (파일 목록)
grep -rl "사실혼" 가사/

# 선고일자 범위로 조회
git log --since="2024-01-01" --until="2024-12-31" --oneline

# 판례일련번호로 커밋 검색
git log --all --grep="판례일련번호: 145683"
```

## 메타데이터 (YAML Frontmatter)

| 필드 | 설명 |
|------|------|
| `판례일련번호` | 판례 고유 식별자 (**안정적 참조 키**) |
| `사건번호` | 법원이 부여한 사건번호 |
| `사건명` | 판례 제목 |
| `법원명` | 선고 법원 (약어는 정식 명칭으로 정규화) |
| `법원등급` | `대법원` / `하급심` / `미분류` |
| `사건종류` | `민사` `형사` `일반행정` `세무` `가사` `특허` `기타` |
| `선고일자` | 선고 날짜 (YYYY-MM-DD) |
| `출처` | law.go.kr 판례 URL |

본문 구성: `판시사항` / `판결요지` / `참조조문` / `참조판례` / `판례내용`.

## 반드시 주의할 점

1. **commit hash는 안정 식별자가 아니다.** 파이프라인 개선 시 전체 재구성 후 **force-push**(모든 hash 변경). 장기 참조는 hash 대신 **`판례일련번호` + `선고일자` + law.go.kr URL**로. 동기화: `git fetch --all && git reset --hard origin/main`.

2. **1970-01-01 이전 선고 판례**는 Git 한계로 commit 날짜가 1970-01-01로 고정. 실제 선고일은 frontmatter `선고일자`를 신뢰.

3. **단기(檀紀)→서기 변환**: 원천 API가 일부 오래된 판례의 선고일자를 단기 4자리 연도(4200–4330)로 줄 때 `서기 = 단기 − 2333`으로 변환해 기록. 단, 사건번호 속 단기 연도(예: `4289행5`)는 식별자라 그대로 보존. 변환된 일부 건은 실선고일과 ±1년 오차 가능 → 정확한 날짜는 본문 확인.

4. **가운뎃점**: 사건종류 `선거·특별`처럼 `·`가 디렉토리명에 쓰인다. 검색·매칭 시 정확한 문자 사용.
